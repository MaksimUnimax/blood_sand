## Что сохранять после каждого блока

- Реально изменённые исходники, незавершённые изменения и diff. Нельзя сохранять только пересказ.
- Точный base/candidate commit или хеши файлов, затронутые A-ID и TA-ID, карта зависимостей.
- Сам тестовый runner, stdout/stderr, exit code, результаты каждой проверки и их evidence-path.
- Успешные и неуспешные проверки раздельно; текущий дефект; точное следующее действие.
- WIP commit, публикация без force, remote readback изменённых файлов.

Сохранение обязательно после каждого связного изменения или ограниченной группы тестов, ПЕРЕД следующим долгим действием и перед окончанием запуска. Не ждать готовности всей сборки. FAIL также сохраняется. Во время длинного теста результаты пишутся по одной проверке с flush/fsync. Поздний сбой не должен стирать уже полученные записи.

Один checkpoint не должен содержать токены, личные данные покупателей или несанкционированные изменения других проектов. Старые `reference-*` не переписываются. При движении remote HEAD изменения сначала сверяются; force push запрещён.

`WIP сохранён` не означает `патч готов`. Готовность по-прежнему определяется полным применимым patch gate, а LIVE PASS — реальными установленными тестами.

## При обрыве или сбое инструментов

Не повторять десятки одинаковых неуспешных вызовов. Сохранить всё доступным рабочим способом. При недоступной публикации создать recovery-архив исходников, diff, тестов, evidence и cursor, выдать его пользователю и явно указать `PUBLICATION_FAILED`. Не заявлять, что кандидат собран или тесты прошли, без сохранённых байтов и протоколов.
