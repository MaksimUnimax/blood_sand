## Что сохранять после каждого блока

- Реально изменённые исходники, незавершённые изменения и diff. Нельзя сохранять только пересказ.
- Точный base/candidate commit или хеши файлов, затронутые A-ID и TA-ID, карта зависимостей.
- Сам тестовый runner, stdout/stderr, exit code, результаты каждой проверки и их evidence-path.
- Успешные и неуспешные проверки раздельно; текущий дефект; точное следующее действие.
- WIP commit, публикация без force, remote readback изменённых файлов.

Сохранение обязательно после каждого связного изменения или ограниченной группы тестов, ПЕРЕД следующим долгим действием и перед окончанием запуска. Не ждать готовности всей сборки. FAIL также сохраняется. Во время длинного теста результаты пишутся по одной проверке с flush/fsync. Поздний сбой не должен стирать уже полученные записи.

Один checkpoint не должен содержать токены, личные данные покупателей или несанкционированные изменения других проектов. Старые `reference-*` не переписываются. При движении remote HEAD изменения сначала сверяются; force push запрещён.

`WIP сохранён` не означает `патч готов`. Готовность по-прежнему определяется полным применимым patch gate, а LIVE PASS — реальными установленными тестами.

## При обрыве или сбое инструментов

Не повторять десятки одинаковых неуспешных вызовов. Сохранить всё доступным рабочим способом. При недоступной публикации создать recovery-архив исходников, diff, тестов, evidence и cursor, выдать его пользователю и явно указать `PUBLICATION_FAILED`. Не заявлять, что кандидат собран или тесты прошли, без сохранённых байтов и протоколов.

## Дополнение 2026-09-12 — фиксация ВО ВРЕМЯ работы

Владелец повторно потребовал промежуточного сохранения после обрыва доставки ответа в длинной цепочке инструментов. Это дополнение уточняет периодичность уже существующего правила, не разрешает новый runtime-патч и не заменяет patch gate.

Актуальную точку продолжения брать из свежего `EXECUTION_CURSOR.json`, его `current_authorities` и `latest_work_checkpoint`. Исторические абзацы выше описывают recovery 2026-09-11, а не отменяют поздние remote-результаты. Для текущего корректирующего переноса действует `parity_reaudit/SUPERSEDING_PATCH_AUTHORITY_2026-09-12.md` в указанной cursor области приоритета. Контрольная точка обрыва: `parity_reaudit/CHECKPOINT_2026-09-12_INTERRUPTED_AUDIT.md`.

Обязательная граница сохранения: каждый законченный смысловой блок, каждый обнаруженный дефект, каждая ограниченная группа тестов; дополнительно перед долгим действием и перед завершением запуска. В длинном read/search-проходе — не позднее пяти содержательных вызовов без промежуточной записи. Незавершённый блок сохраняется как `IN_PROGRESS` с точным местом остановки, а не растягивается до конца всего аудита.

Для частично прочитанного файла записывать path, immutable ref/blob SHA, прочитанные диапазоны строк и следующий диапазон. Для найденного патча разделять: ветка найдена; metadata прочитана; diff прочитан; связанные MD прочитаны; причина доказана; WB-сопоставление выполнено; тест выполнен. Эти состояния не взаимозаменяемы. Обрезанный ответ инструмента не считается полным чтением.

Каждый блок оставляет в `WORK_LOG.jsonl` запись о цели, сделанных действиях, источниках, результате/ошибке/неопределённости, реально изменённых файлах и diff, test runner/stdout/stderr/exit code при наличии, оставшейся работе и следующем действии. Большие протоколы хранить отдельными файлами и указывать точные пути. При изменении точки продолжения обновлять `EXECUTION_CURSOR.json`; согласовывать feature/test ledgers только на основании соответствующей evidence.

После публикации выполнять remote readback. В чате сообщать короткий результат блока и сохранённый commit, а не оставлять владельцу десятки инструментальных вызовов без понятного промежуточного итога. Неопределённый исход записи сначала проверять чтением remote; не повторять запись вслепую. Если remote недоступен, сохранить локальные WIP и recovery-файлы, явно указав, что публикация не подтверждена.

Старые события не удалять и не переписывать задним числом. Восстановленную из текущего remote сводку помечать `RECOVERED_*`, отделять от новых выполненных действий. Запрет на реальные WB API-вызовы в текущем parity rework и другие ограничения cursor сохраняются.
