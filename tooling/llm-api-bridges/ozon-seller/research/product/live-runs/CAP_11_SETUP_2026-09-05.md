# CAP-11 — Promotions/actions — SETUP

Status: ACTIVE

Canonical job:

`Какие акции и скидочные механики продавца сейчас активны в моём кабинете Ozon и какие товары реально участвуют в них? Используй отдельные promotion/action API Ozon, а не только встроенный блок marketing_actions из ответа по ценам.`

Capability target: prove the worker recognizes promotions/actions as a dedicated Ozon surface, can discover current active seller actions without operator-supplied action IDs, and can drill into product participation when actions exist.

Contract authority:
- `seller_actions_list` -> `POST /v1/seller-actions/list`, all accounts, explicit `offset/limit` pagination; `status` is an array over `ACTIVE|ENDED|PLANNED|PAUSED`.
- `seller_action_products` -> `POST /v1/seller-actions/products/list`, requires one `action_id`, `limit` 1..100, optional cursor.

Method:
1. Read all active seller actions with `status:["ACTIVE"]`, `limit:100`, `offset:0`.
2. If listing indicates more than one page, continue explicit pagination before declaring the action set complete.
3. If active actions exist, select the returned action IDs from provider evidence and inspect product participation with the dedicated action-products surface; follow its cursor when required.
4. Do not treat CAP-10 embedded `marketing_actions` as a substitute for the dedicated promotions capability.
5. Preserve explicit provider wording/type/status rather than inventing a promotion taxonomy.

Checkpoint: `CAP_11_ACTIVE_RUN_1_NEXT`
