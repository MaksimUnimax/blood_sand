# CAP-17 — Advertising campaigns — SETUP

Status: ACTIVE

Canonical job:

`Какие рекламные кампании Ozon у меня сейчас есть и какие из них активны, остановлены или завершены? Покажи campaign ID, тип/объект рекламы и текущий state из Performance API; не пытайся выводить список кампаний из расходов Seller Analytics.`

Capability target: prove the worker recognizes advertising campaign inventory as the separate Ozon Performance API family, can enumerate campaigns without operator-supplied IDs, preserve provider campaign states, and use explicit pagination when required.

Active registry authority:
- `performance_campaigns` -> Performance API `GET /api/client/campaign`, READ_SAFE/current, cluster `advertising_performance`, section `campaigns`, purpose: campaign list.
- accepted params: optional `campaignIds`, `advObjectType`, `state`, `page`, `pageSize`.
- known provider states accepted by the current Bridge contract include RUNNING, PLANNED, STOPPED, INACTIVE, ARCHIVED, MODERATION states and FINISHED.

Frozen method:
1. Start with `performance_campaigns` page 1, pageSize 100 without a state filter so the worker can see the current campaign inventory and provider states instead of assuming only running campaigns matter.
2. If the provider response proves another page exists, continue with one explicit command per page; no hidden autopagination.
3. Preserve campaign IDs and state/type fields exactly enough to separate active/running vs stopped/finished/inactive states.
4. Do not use Performance statistics/expense reads in CAP-17; those belong to CAP-18.
5. Do not infer campaign state from spend or Seller sales analytics.

Scoring: standard CAP fields.

Checkpoint: `CAP_17_ACTIVE_RUN_1_NEXT`
