## Mandatory orchestration correction — 2026-09-06

The earlier workflow incorrectly forced one operator round trip per `finance_accrual_by_day` calendar date.

This was a process defect.

`finance_accrual_by_day` accepts one date per explicit command, but the Bridge supports multiple explicit `OZON_API_V1` commands in one assistant response and executes them as `sequential_batch_single_delivery`.

Therefore:

`ONE DATE PER COMMAND != ONE COMMAND PER ASSISTANT TURN`

For independent first-page date reads where all dates are known in advance:

`EXPLICIT_BATCH_FIRST_FOR_INDEPENDENT_READS`

The assistant should emit multiple complete commands in one response, using a bounded explicit batch rather than waiting for the operator after every date.

Stepwise execution is required only when the next command depends on prior output, including:

- non-empty `last_id` requiring a continuation token;
- an ID needed for the next operation is discovered in the previous response;
- provider/causal failure changes the next experiment;
- a safety/privacy/entitlement or side-effect decision requires inspection;
- a stop condition can make later commands unnecessary.

A non-empty `last_id` from one day does NOT invalidate independent first-page commands for other already-known dates. The continuation for that specific day is queued later as its own explicit dependent command.
