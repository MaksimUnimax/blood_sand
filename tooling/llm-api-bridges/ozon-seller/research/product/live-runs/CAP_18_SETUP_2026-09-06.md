# CAP-18 — Advertising statistics — SETUP

Status: ACTIVE

Canonical job:

`Сколько я потратил на рекламу Ozon за 29 августа — 4 сентября 2026 года, сколько продаж реклама атрибутировала, как менялись расходы и ДРР по дням и какие кампании/товары дали основной результат? Используй именно Performance API statistics; не подменяй рекламные расходы Seller Analytics.`

Capability target: prove the worker recognizes advertising statistics as the separate Ozon Performance API statistics family, can combine aggregate expense, daily dynamics and campaign/product attribution, and does not confuse Performance-attributed sales with Seller Analytics revenue.

Active registry authority:
- `performance_expense` -> `GET /api/client/statistics/expense/json`, READ_SAFE/current, purpose: advertising expense statistics.
- `performance_daily` -> `GET /api/client/statistics/daily/json`, READ_SAFE/current, purpose: daily advertising statistics.
- `performance_campaign_product` -> `GET /api/client/statistics/campaign/product/json`, READ_SAFE/current, purpose: campaign/product advertising statistics.

Current contract authority:
- `performance_expense` / `performance_daily` accept optional `campaignIds`, `dateFrom`, `dateTo` in YYYY-MM-DD form.
- deterministic date gate allows an inclusive range up to 62 days for these statistics reads.
- `performance_campaign_product` is under the strict Performance alternate-date contract; when that drilldown is reached, use an explicit RFC3339 `from`/`to` pair rather than inventing a date boundary.

Frozen method:
1. Read `performance_expense` for `2026-08-29`..`2026-09-04` without campaign IDs to establish the account-level Performance expense/attributed-sales surface.
2. Read `performance_daily` for the same period to verify day-level dynamics and DRR components from Performance itself.
3. If the canonical answer still needs campaign/product attribution, read `performance_campaign_product` for the same interval using RFC3339 `from`/`to`.
4. Preserve Performance semantics; do not call attributed advertising sales "total seller revenue".
5. Do not reuse the CAP-17 campaign inventory as a substitute for statistics and do not use Seller Analytics as the advertising-spend authority.
6. One logical command -> at most one physical business request per run; no hidden autopagination.

Scoring: standard CAP fields.

Checkpoint: `CAP_18_ACTIVE_RUN_1_NEXT`
