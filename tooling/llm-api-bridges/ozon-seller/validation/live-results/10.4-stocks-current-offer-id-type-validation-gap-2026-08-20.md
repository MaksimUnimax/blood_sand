# Ozon Bridge v0.1.19 — live test 10.4

Date: 2026-08-20
Account boundary: ordinary Seller account
Operation: `stocks_current`
Scenario: wrong type for documented `filter.offer_id`; scalar string supplied instead of an array

## Command

```text
OZON_API_V1
{"operation":"stocks_current","params":{"filter":{"offer_id":"Чётки - Талисман в машину \"RSOTM\"."},"limit":1}}
```

- Bridge version: `0.1.19`
- Capability probe: not performed / not needed

- Operation accepted as `stocks_current`
- `external_request_executed=true`

## Verdict

**VALIDATION GAP**

The bridge did not enforce the expected local type boundary for `filter.offer_id`. A scalar string was accepted unchanged and sent to Ozon as one physical business request. Ozon rejected the malformed provider request with HTTP 400 / code `3`.

This proves missing bridge-side type validation for this `stocks_current.filter` field. It does not indicate that the provider accepts scalar `offer_id`; the provider explicitly rejected this request.
