## What was repaired

The old blanket `MIXED_HELP_AND_API` rejection was removed from the executable worker. `OZON_HELP_V1`, `OZON_HELP_V2`, and `OZON_API_V1` are now discovered as typed envelopes in one source-ordered batch. API-envelope semantics continue to delegate to `OzonContract.discoverCommands`; HELP-envelope semantics continue to delegate to `OzonGuidance.parseHelp`.

Guidance remains local: it reports `external_request_executed=false` and contributes zero physical provider business requests. Only `kind="command"` entries proceed through command capability/privacy/query planning and provider execution. Existing accounting remains: one explicit API command causes at most one provider business request; HELP entries do not increase the physical business-request count.

The startup prompt/current authority documentation now states that the command boundary is an envelope rather than an assistant response, Markdown code fence, or Manual UI capture. It allows independent HELP/API envelopes in one response in source order, forbids hidden retry/automatic pagination/polling/fan-out, and requires fresh actual opaque values for dependent chains.
