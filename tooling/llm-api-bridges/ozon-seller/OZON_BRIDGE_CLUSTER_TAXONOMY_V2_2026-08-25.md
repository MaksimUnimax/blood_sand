# Ozon Bridge — Cluster Taxonomy V2

Дата: 2026-08-25  
Статус: целевая схема командной навигации для полного read-only покрытия Seller API + существующего Performance API.

## Правило совместимости

Шесть существующих cluster ID не переименовываются: `sales_analytics`, `stock_inventory`, `search_visibility`, `fulfillment_supply`, `advertising_performance`, `account_access`. Их текущие alias остаются в тех же кластерах. Новые кластеры только дополняют схему. Это исключает ломку существующих prompt/guide сценариев.

## Целевые кластеры

1. `sales_analytics` — **Продажи и агрегированная бизнес-аналитика**. Сохраняется. Периоды, выручка, заказы и агрегированные показатели.
2. `stock_inventory` — **Остатки, движение и оборачиваемость**. Сохраняется и расширяется: FBO/FBS по складам, аналитика остатков, отчёты по остаткам/движению.
3. `search_visibility` — **Поиск и видимость товаров**. Сохраняется и расширяется Premium-поисковыми запросами.
4. `fulfillment_supply` — **FBO/FBP поставки и грузоместа**. Сохраняется и расширяется безопасными статусами, списками, складами, таймслотами и документами без файлов.
5. `advertising_performance` — **Реклама Performance API**. Сохраняется отдельно от Seller API; 4 текущих read-only alias, не входят в 303 Seller paths.
6. `account_access` — **Аккаунт, роли и доступ**. Сохраняется; сюда же seller/info для определения подписки и доступности функций.
7. `catalog_products` — **Каталог и карточки товаров**. Новый: товары, атрибуты, категории, изображения, лимиты, описание, видимость.
8. `pricing_promotions` — **Цены, акции и стратегии**. Новый: чтение цен, акций, кандидатов, стратегий и их состояния; изменение цен/акций не допускается.
9. `warehouses_logistics` — **Склады, география и логистические настройки**. Новый: склады Ozon/продавца, методы доставки, ограничения и логистическая конфигурация.
10. `fbs_orders_delivery` — **FBS/FBO отправления и доставка**. Новый: списки, статусы, причины, акты без опасных файлов; детальные отправления только с фильтрацией полей/редакцией PII.
11. `returns_cancellations` — **Возвраты и отмены**. Новый: списки, статусы, причины, утилизация и возвратная логистика.
12. `finance_accounting` — **Финансы и расчёты**. Новый: начисления, баланс, реализация, взаиморасчёты, выкуп и JSON-финансовые документы.
13. `reports_documents` — **Выгрузки и отчёты**. Новый: явные многошаговые read-workflow для отчётов. Создание отчёта не считается изменением бизнеса.
14. `reviews_questions` — **Отзывы и вопросы**. Новый: безопасные счётчики и списки; текстовые поверхности только через строгую фильтрацию/редакцию.
15. `certification_compliance` — **Сертификаты и соответствие**. Новый: справочники, статусы и чтение сертификатов; операции изменения сертификатов не входят.
16. `seller_quality` — **Качество продавца**. Новый: рейтинги, история, FBS error index; устаревшая Average Delivery Time не добавляется.
17. `notifications_integrations` — **Уведомления и интеграции**. Новый: чтение списка и типов уведомлений; проверка произвольного URL запрещена.
18. `customer_communications` — **Коммуникации с покупателями**. Новый кластер-заглушка политики: текущие chat/file/history/list не исполняются из-за персональных данных.

## Premium — не кластер

Premium, Premium Lite, Premium Plus и Premium Pro — это признак доступа к конкретной операции/режиму, а не намерение пользователя. Поэтому Premium не дублирует команды в отдельных кластерах. Метаданные операции содержат `subscription_requirement`; capability проверяется перед планированием запроса.

## Метаданные каждой операции

Для каждого alias обязательны: `source_api`, фиксированный Ozon path/method, primary `cluster`, `key_roles_required`, `subscription_requirement`, `feature_stage`, `pii_policy`, параметрический контракт, пагинация, prerequisite recipe, response allowlist/redaction, provider quota family и replacement/deprecation metadata. Один alias принадлежит ровно одному primary cluster.

## Автономные prerequisites

Если целевой метод требует product_id, sku, warehouse_id, supply_order_id или другой идентификатор, модель не должна сразу просить его у пользователя. Guidance сначала предлагает безопасный read-only prerequisite, если Bridge умеет получить идентификатор сам. Каждый prerequisite — отдельная явная команда и отдельный физический запрос. Скрытых циклов, fan-out и скрытой пагинации нет.

## Guidance при недоступном методе

Bridge должен различать четыре ситуации: (1) метод существует upstream и уже выставлен Bridge; (2) метод существует upstream, но ещё не выставлен; (3) метод выставлен, но текущему ключу/подписке недоступен; (4) метод сознательно запрещён политикой Bridge. Нельзя превращать ситуацию (2) или (3) в фразу «Ozon API этого не умеет».

## Источники решений

- фактический `/v1/roles` текущего Seller API ключа — источник точного списка 303 путей;
- текущие repository authorities `OZON_READ_ONLY_ALLOWLIST_V1.json`, `OZON_03A3_COMPLETENESS_V1.json`, `OZON_GUIDED_COMMAND_DISCOVERY_SPEC_2026-08-21.md`;
- Ozon-owned Seller API/OpenAPI и уведомления об изменениях — источник смысла, версий, Premium/beta/deprecation;
- сторонний OpenAPI mirror используется только как удобный индекс для сверки и никогда не заменяет Ozon-owned contract при кодировании.
