Ozon API credentials

Seller API — существующий контур. Его роли и проверка через /v1/roles не изменены.

Performance API — отдельный сервисный аккаунт для рекламы. Bridge использует только READ allowlist; mutation endpoints блокируются кодом независимо от возможностей ключа.

Backup v2 содержит Seller Client-Id/Api-Key и Performance Client ID/Client Secret и является секретом. Старые Seller-only backup v1 продолжают импортироваться.

Обе пары credentials хранятся только в chrome.storage.local, не передаются content script и не включаются в результаты/диагностику. Performance Bearer token хранится только в памяти service worker. Исключение — явный локальный export backup по кнопке пользователя.

Как работает
  1. Привязка: сначала явно привяжите текущий AI-диалог.
  2. Manual: собственная кнопка Ozon у структурно найденного code block передаёт его актуальный raw text bridge parser и может инициировать ровно один allowlisted business request; для Performance API допускается отдельный token bootstrap.
  3. Autorun: расширение сканирует полный завершённый assistant message, структурно извлекает все OZON_API_V1, выполняет provider requests строго последовательно, сохраняет результаты временно и затем делает одну финальную доставку.
  4. Gate: разрешены только фиксированные read-only operation aliases; customer-PII surface posting_fbs_get заблокирован.
  5. Recovery: неизвестный исход уже начатого provider request никогда не replay-ится автоматически.
