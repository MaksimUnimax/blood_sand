# Ozon Bridge Step 4 — scope freeze

Date: 2026-08-18
Status: scope only; implementation follows on the Step-4 development branch.

Accepted base:

- Step-3 frozen production target: `eae8988f5baf8c7ead5a82371c9b1057295c906d`
- Step-3 acceptance decision commit: `6a644e57ee36ac4aa48c0a93464438c6595adc0e`

Step 4 is the final planned engineering step before controlled live acceptance.

In scope:

- verified reusable provider-result cache/prefetch only when semantic equivalence or a reviewed safe provider superset can be proven;
- cache provenance/freshness attached to logical results;
- no cross-account cache reuse; Seller account identity remains internal;
- no reuse of unverified/malformed/provider-error responses;
- deterministic reviewed semantic acquisition profiles/aliases that compile to existing strict operations rather than arbitrary provider calls;
- preserve Step-1 entitlement planning, Step-2 coalescing/projection, and Step-3 quota/verifier/error semantics;
- integrated multi-tab, multi-conversation and ChatGPT/Alice synthetic QA;
- prepare a separate final controlled live-acceptance plan for facts that require the operator's real logged-in browser/profile and real Ozon responses.

Out of scope:

- arbitrary assistant-defined cache keys, TTLs, URLs, operations or headers;
- unsafe top-N/window expansion or cross-filter/cross-dimension derivation;
- hidden provider retry, polling or pagination;
- bypassing Step-3 quota state because a cache miss occurs;
- declaring live ChatGPT/Alice/Ozon behavior accepted from synthetic QA alone;
- canonical release promotion before final live acceptance.

Protected surfaces:

- native-Copy structural code-block binding and extension overlay;
- ChatGPT delivery FSM and Alice-specific lifecycle separation;
- Step-1 capability/entitlement planner;
- Step-2 compatibility/coalescing/projection semantics;
- Step-3 quota-family scheduler, durable wait/no-replay, response verifier and safe-error policy;
- fixed provider hosts/read-only operation registry and credential isolation.

Step-4 acceptance requires an independently frozen implementation SHA plus a standalone Codex validation plan. After synthetic acceptance, final controlled live acceptance remains a separate operator gate.
