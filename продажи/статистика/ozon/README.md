# Ozon — ежемесячная статистика поисковых запросов

Назначение этого раздела — **накапливать фактические поисковые фразы Ozon по товарам «Кровь и песок» без аналитической интерпретации на этапе сбора**.

## Зачем

Seller API даёт детализацию поисковых запросов только за ограниченное доступное окно без Premium. Поэтому вместо разового снимка ведём постоянный накопительный журнал: раз в месяц повторяем сбор по всему текущему Ozon-ассортименту и добавляем новый период. Через 12 месяцев получаем собственную годовую базу запросов по SKU.

Это хранилище — evidence/data layer. SEO-анализ, кластеризация, выводы о релевантности и изменения карточек выполняются отдельно и не записываются в этот сырой журнал.

## Канонический источник

Bridge: `ozon-llm-api-bridge`.

Операция для фраз: `product_queries_details` (`POST /v1/analytics/product-queries/details`).

Правило исполнения:
- одна `OZON_API_V1` команда создаёт не более одного физического business request;
- несколько независимых команд можно отправлять одним sequential batch;
- скрытые retry, pagination-loop и fan-out запрещены;
- при ошибке конкретный request не повторяется автоматически;
- сохраняем только фактически возвращённый результат.

## Накопительный файл

`monthly_search_queries.tsv`

Поля:
- `capture_date` — дата сохранения результата;
- `bridge_version` — версия Ozon Bridge;
- `request_id` — идентификатор конкретного вызова;
- `date_from`, `date_to` — фактический аналитический период, который вернул Ozon;
- `sku` — Ozon SKU;
- `query_index` — порядок фразы в ответе Ozon;
- `query` — поисковая фраза;
- `unique_search_users`, `unique_view_users`, `view_conversion`, `position`, `order_count`, `gmv`, `currency` — поля safe projection из фактического ответа.

`NULL` означает, что provider/Bridge вернул `null`; это не заменяется нулём и не интерпретируется.

## Первый месячный цикл

Период: `2026-08-13` — `2026-09-10`.

Целевой ассортимент: 76 актуальных Ozon SKU из канонического `marketing/data/normalized/marketplace/ozon/20260826__ozon__product-master__fresh-current76.csv`.

Первый уже полученный фрагмент:
- SKU `1636048691` (`Печать Велеса`);
- request_id `c527ff0d-53dc-4ea1-9143-04142d37ddd5`;
- 10 поисковых фраз;
- сохранён в `monthly_search_queries.tsv`.

Оставшиеся SKU этого месячного цикла дописываются после фактических `OZON_RESULT_V1`. Никакой SEO-аналитики до завершения сбора по всему ассортименту в этом разделе не делаем.

## Ежемесячное правило

1. Зафиксировать актуальный список Ozon SKU.
2. Запустить `product_queries_details` по каждому SKU на доступном месячном окне.
3. Сохранить каждый успешный результат с точным `request_id`, периодом и версией Bridge.
4. Не удалять старые периоды и не пересчитывать исторические строки задним числом.
5. Новые месяцы только добавлять в накопительный TSV.
6. После накопления данных аналитические производные хранить отдельно от этого raw/evidence журнала.
