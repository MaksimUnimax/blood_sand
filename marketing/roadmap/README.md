# Roadmap — от стратегии до релиза

Версия: 1.5  
Дата: 2026-08-10  
Статус: **рабочий управляющий roadmap проекта**

Этот каталог задаёт последовательность работы от текущей маркетинговой стадии до production-релиза сайта.

Он дополняет `marketing/RESEARCH_ROADMAP.md`: старый документ описывает исследовательские направления, а этот roadmap управляет **всем проектом целиком**, включая исследования, продуктовые решения, контент, разработку, аналитику, QA, запуск и пострелизное измерение.

## Жёсткое правило структуры

Roadmap имеет **ровно два уровня**:

1. **Пункт** — крупный этап проекта.
2. **Шаг** — непосредственно выполняемая часть этого пункта.

Глубже дерево **никогда не дробится**.

Допустимо:

`02 → 02.1, 02.2, 02.3`

Недопустимо:

`02 → 02.1 → 02.1.1`

У шага могут быть описание, результат, критерии проверки, источники, заметки и артефакты, но это не новые вложенные шаги.

Когда мы доходим до нового пункта, создаётся отдельный файл `NN_*.md`, где этот пункт один раз разбивается на конечный список непосредственно выполняемых шагов. После этого шаги не дробятся дальше.

До начала выполнения каждого нового пункта обязательно:

- записать конечный список его шагов;
- оценить примерное число рабочих ранов/итераций на весь пункт;
- определить ожидаемый результат каждого шага;
- определить критерий завершения пункта;
- определить зависимости и блокеры.

## Обязательное правило статусов

- `[ ]` — не начато;
- `[~]` — в работе;
- `[x]` — выполнено;
- `[!]` — заблокировано/поставлено на обязательную паузу.

После выполнения каждого шага его статус меняется в детальном файле пункта.

После выполнения всех обязательных шагов пункта:

1. сам пункт помечается `[x]` в этом файле;
2. в его детальном файле фиксируется итоговый результат;
3. следующий пункт не начинается автоматически, пока не проверен критерий завершения текущего.

Обсуждение не считается выполнением: нужен зафиксированный результат/артефакт/решение/измерение.

## Оценка ранов

`Ран` — одна содержательная рабочая итерация: исследование, измерение, аналитический проход, подготовка артефакта, реализация или проверка, которую можно отдельно завершить и зафиксировать.

Оценки ниже предварительные. Перед началом каждого пункта диапазон уточняется в его отдельном файле.
