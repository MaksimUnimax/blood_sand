# 03 — Полностью измерить поисковый спрос / Wordstat

Статус: **[~] В РАБОТЕ**  
Дата начала: 2026-08-04  
Оценка: **примерно 37–54 рана**  
Фактически выполнено: **1 шаг; API-съём этого пункта ещё не начат**

## Почему оценка существенно выше первоначальных 6–12 ранов

После появления рабочего Wordstat Manual Bridge стало понятно, что один executable `WORDSTAT_API_V1` command выполняет ровно один API request и результат возвращается отдельным наблюдением. Для качественного покрытия нужны отдельные GetTop / operator / Dynamics / device / region measurements. Поэтому прежняя оценка 6–12 ранов была слишком грубой.

Денежная стоимость API при текущих тарифах мала; главный ресурс — число отдельных измерений и их проверка. Перед **каждым** executable Wordstat command обязательно заново проверяется актуальная официальная цена Яндекса и пользователю сообщается стоимость именно этого вызова.

## Цель пункта

Получить decision-grade картину человеческого поискового спроса в Яндексе по России для товарного, автомобильного, информационного/сравнительного и подарочного слоёв, сохранить raw/normalized evidence и обновить Query Evidence Ledger без подмены Search/Alice/commerce данных Wordstat-частотностью.

## Критерий завершения пункта

Пункт закрывается, когда:

- основные root-кластеры измерены через GetTop;
- для приоритетных коммерческих и смысловых запросов измерены operator variants, необходимые для отделения broad от более узких формулировок;
- для репрезентативных cluster leaders снята сезонность;
- device/region measurements выполнены там, где они способны изменить решение;
- Tier 2 расширен только по фактическим результатам, а не массово заранее;
- все использованные measurements имеют raw evidence и normalized observations;
- Query Evidence Ledger обновлён;
- существует итоговый R1 Wordstat report с выводами и ограничениями;
- явно отделено, что Wordstat доказывает, а что должен проверить следующий Yandex SERP/Alice этап.

# Шаги

## [x] 03.1 — Зафиксировать decision-grade scope и план измерений

**Оценка:** 1 ран.  
**Статус:** выполнено 2026-08-04.

Создан execution plan:

- `marketing/research/R1_WORDSTAT_EXECUTION_PLAN_2026-08-04.md`

Принято не выполнять механически одинаковый набор дорогих по времени measurements для всех 37 seed-фраз. Вместо этого используется staged design: cluster discovery → operator precision для high-value запросов → seasonality → selective device/region → evidence-driven Tier 2.

Это сохраняет полноту для принятия решений и резко уменьшает бессмысленные повторные API-вызовы.

## [~] 03.2 — Снять GetTop по root-кластерам и сформировать фактическую карту формулировок

**Оценка:** примерно 13–17 ранов API + 1 аналитический проход.

Root set включает товарное ядро, варианты медведь/волк, автомобильный use case, значение/сравнение и подарок. `печать велеса` уже имеет live measurement и повторно без причины не запрашивается.

Ожидаемый результат: raw + normalized GetTop observations, фактические phrases/associations, обнаруженные Tier 2 кандидаты, broad cluster signals.

## [ ] 03.3 — Измерить operator variants для high-value запросов

**Оценка:** примерно 12–18 ранов.

Для наиболее важных коммерческих/смысловых запросов измеряются quoted/exact-form варианты по правилам Wordstat. Не каждый long-tail получает operator measurements автоматически: приоритет даётся запросам, способным изменить page/cluster decision.

Ожидаемый результат: broad и более узкие значения не смешиваются; видно, где высокий broad создаётся большим хвостом, а где сама формулировка имеет устойчивый спрос.

## [ ] 03.4 — Снять сезонность по репрезентативным cluster leaders

**Оценка:** примерно 4–6 ранов.

GetDynamics используется для лидеров товарного, автомобильного, meaning и gift кластеров. Минимальная цель — 24 месяца помесячно там, где API/история это позволяет.

Ожидаемый результат: выявлены сезонность, пики/просадки и риск трактовать один 30-day snapshot как постоянный спрос.

## [ ] 03.5 — Проверить device и region differences там, где они decision-useful

**Оценка:** примерно 4–7 ранов.

Не делается полный device/region cube для каждого запроса. Проверяются репрезентативные high-value запросы, прежде всего product/automotive. Region distribution используется только если результат способен изменить geo/content/commerce решение; доставка остаётся по России.

Ожидаемый результат: подтверждено, есть ли значимая device/geo специфика или её можно не учитывать при приоритизации страниц.

## [ ] 03.6 — Расширить Tier 2 и закрыть пробелы по evidence

**Оценка:** примерно 3–7 ранов.

Новые measurements назначаются только для фраз, которые появились в GetTop или имеют сильную коммерческую связь и способны изменить решение. Шумовые associations и явно нерелевантные темы не получают дальнейшего бюджета.

Ожидаемый результат: измерено не всё возможное, а всё существенное для следующего SERP/Alice этапа.

## [ ] 03.7 — Нормализовать полный R1 dataset, обновить Ledger и закрыть Wordstat-этап

**Оценка:** 2–3 аналитических рана.

Ожидаемый результат:

- полный normalized Wordstat dataset;
- обновлённый `marketing/data/ledger/query_evidence_ledger.csv`;
- итоговый R1 report;
- зафиксированные H signals без выдумывания A/C/O;
- список запросов, которые переходят в roadmap 04 для прямого Yandex SERP/Alice measurement;
- пункт 03 закрыт только после quality gates.
