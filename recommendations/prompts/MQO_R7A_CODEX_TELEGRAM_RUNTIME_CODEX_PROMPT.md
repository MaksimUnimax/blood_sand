3. TELEGRAM CODEX CALLBACK WORKFLOW

Wire the production handler/service path for these actions:
- codex
- regenerate
- retry_codex
- choose_codex

NEW + codex:
- capture active profile;
- create exactly one draft attempt for the same question;
- set it current;
- transition NEW -> CODEX_RUNNING;
- start generation through the runner abstraction.

REVIEW + regenerate:
- preserve old revisions and attempts;
- capture currently active profile;
- create a new attempt for the same question/Q-ID;
- transition REVIEW -> CODEX_RUNNING;
- start generation.

CODEX_ERROR + retry_codex:
- create a new attempt for the same question/Q-ID;
- use the active profile at retry time;
- transition CODEX_ERROR -> CODEX_RUNNING;
- start generation.

choose_codex:
- persist codex1/codex2/codex3 through existing settings validation;
- perform zero generation;
- create zero draft attempts by itself.

Duplicate codex/regenerate/retry taps while the question is already CODEX_RUNNING must not create a second active attempt or second runner invocation.

Malformed/stale callbacks must not launch generation.
